# Video Downloadest

Captures MediaSource audio/video chunks through a Chromium extension and sends them directly to a local Native Messaging host. Streams from the same MediaSource form one capture; separate players do not get mixed together. The extension does not use localhost HTTP or a TCP port.

## Run

1. Run the macOS companion app to install the Native Messaging host and managed Node.js/FFmpeg runtimes.
2. Load the extension folder as an unpacked extension in Chrome. The companion app opens the folder and Chrome extensions page for you.
3. After updating the extension, reload it and reload the player page.
4. Videos stay paused until you choose playback: the extension removes autoplay attributes and blocks automatic `play()` calls. Click **Download & play** on the video you want to save. The button appears centered horizontally in the lower third of each paused video, including videos added after page load. Keep the page open until the progress overlay reports `✅ Saved`. The player’s existing play controls play normally without uploading, saving, or automatic seeking.

## Companion app (macOS developer build)

The companion app registers the Native Messaging host with Chrome, reveals the unpacked extension directory, and opens the saved videos folder. Package it on Apple Silicon with `./scripts/package-companion-macos.sh`; this creates `dist/Video Downloadest-0.1.0.dmg` with an Applications shortcut and install guide. The app downloads the latest Apple Silicon Node.js LTS from nodejs.org and latest stable Apple Silicon FFmpeg build on first launch, verifies both archive checksums, and caches the runtimes per user. Future launches check for updates; a cached runtime is used if an update service is unavailable. See [companion/README.md](companion/README.md) for release signing and notarization.

### Test from source without building the companion

Install Node.js 22 or newer and FFmpeg, then run `./scripts/install-native-host-dev-macos.sh`. The script registers Chrome's Native Messaging host to launch this checkout directly. Set `NODE_BIN` or `FFMPEG_PATH` if the executables are not on `PATH`. In Chrome, load the `extension/` folder as an unpacked extension, reload the extension and player page, then test a capture. Run `./scripts/tail-native-host-logs-macos.sh` to follow host logs. Run `./scripts/uninstall-native-host-dev-macos.sh` to remove the development registration; it leaves a companion-app registration intact.

The extension finishes a capture on a successful `MediaSource.endOfStream()` or the player's `ended` event. It waits for every upload, validates the complete chunk manifest, concatenates each stream in append order, and uses FFmpeg stream copy to mux audio and video into one file under `completed/`, preserving the video SourceBuffer container (for example, MP4 → `.mp4`, WebM → `.webm`). Audio-only and already-muxed streams are also supported. Audio-only MP4 uses `.m4a`. Codecs are copied without re-encoding; unsupported containers or incompatible audio cause an error and retain the captured chunks rather than changing formats. Filenames use Media Session title, player title/accessible label, Open Graph title, then document title, with a capture ID to avoid collisions. Unsafe filename characters are replaced.

Native Messaging and retry queues run inside the extension iframe attached to the player page, without a background service worker. Binary chunks are sent in 16 MiB fragments to stay within Chrome's Native Messaging message limit. Pending uploads are capped at 128 MiB per frame; if the queue fills, that capture stops and you must reload the player page to retry. Keep the page open until saving completes; navigating away, reloading the extension, or discarding the tab loses queued data.

The Native Messaging host writes incoming chunks under `parts/` and uses FFmpeg to save completed captures under `completed/`. A progress overlay on the associated video shows chunks, MiB captured, currently buffered seconds, and buffered percentage when duration is known. It updates on SourceBuffer updates and shows the final save or failure result. Host logs are written to `~/Library/Logs/Video Downloadest/native-host.log`. Failed merges retain chunks under `parts/`; retrying an already received part is safe when its bytes match. If the host disconnects or the extension context closes, queued data is lost; reload the player to start a fresh capture.

## Scope

Captures unencrypted MediaSource streams created in the page's main JavaScript context. Direct media URLs, worker-owned MediaSources, DRM-protected media, and endless live streams are not supported. Uploading and saving start only after clicking **Download & play** for that video. To support players that preload before the click, the extension keeps copies of appended chunks in page memory (up to 64 MiB per MediaSource and 128 MiB per frame). It sends these chunks in their original order only after opting in, including when the source has already finished buffering. Normal playback never sends chunks to the Native Messaging host. If the cache limit is exceeded, that source’s cached bytes are released and the overlay asks you to reload and opt in sooner; it never saves a partial capture. Reloading or closing the page clears the cache. During capture, seeking, codec changes, timestamp edits, or quality switches may produce discontinuities that a simple stream-copy merge cannot repair. On video buffer updates, the extension advances only the opted-in player to the end of the buffered range. Ordinary playback is unaffected. Metadata availability depends on the player; players without exposed track associations may fall back to page metadata. A MediaSource is finalized once; players that reopen it after end-of-stream require a fresh capture.

## Verification

GitHub Actions runs the **Build and verify** check on every pull request and push to `master`, and supports manual runs. It installs locked dependencies with `npm ci`, checks JavaScript syntax, runs the test suite with FFmpeg, and builds an npm package with `npm pack`. The extension and Native Messaging host run directly from source, so there is no compilation step.

Run `npm test`. Tests cover opt-in capture, ordinary playback isolation, existing and dynamically inserted video overlays, preloaded chunk replay, already-buffered completion, cache limits, upload connection startup, chunk ordering, missing/duplicate chunks, stream isolation, filename safety, failed merge retries, extension metadata and completion ordering, and a real FFmpeg audio/video merge. FFmpeg with libx264 and AAC encoding is needed to generate test fixtures. Run `npm run test:browser` for a separate real-Chrome check of early injection, trusted playback controls, source changes, and shadow DOM behavior; set `CHROME_PATH` if Chrome is installed outside the default macOS location.
