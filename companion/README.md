# macOS companion app

`scripts/build-companion-macos.sh` builds an Apple Silicon macOS app at `dist/Video Downloadest.app`. `scripts/package-companion-macos.sh` creates a drag-to-Applications DMG at `dist/Video Downloadest-0.1.0.dmg`, with an Applications shortcut and a short install guide. On launch, the app registers the Native Messaging host with Chrome, opens Chrome's extensions page, opens the unpacked extension directory (`~/Library/Application Support/Video Downloadest/Extension`), and opens the saved-video folder (`~/Videos/Video Downloadest/completed`). Chrome launches the host when the extension connects; captures are sent directly over Chrome Native Messaging and saved under `~/Videos/Video Downloadest/completed`. The app writes host setup and capture logs to `~/Library/Logs/Video Downloadest/native-host.log`.

The extension still needs to be approved and loaded by the user: in Chrome, turn on Developer mode, choose **Load unpacked**, and select the extension folder revealed by the app. The extension has a fixed ID so its origin matches the native host's `allowed_origins` entry. If upgrading from the earlier HTTP version, remove its unpacked extension entry and load this copy again; then reload the player page after extension updates.

The app does not include Node.js or FFmpeg in its bundle and does not require Homebrew or another package manager. On each launch it checks the official Node.js release index and downloads the latest Apple Silicon LTS archive when needed. It also checks for the latest stable Apple Silicon FFmpeg build from [Martin Riedl's FFmpeg build server](https://ffmpeg.martin-riedl.de/). The app verifies both SHA-256 sidecars, then stores runtimes under `~/Library/Application Support/Video Downloadest/{Node,FFmpeg}`. If either update service is unavailable but a cached runtime exists, the app uses the cached copy. FFmpeg publishes source code rather than its own compiled binaries, so the macOS binary comes from this third-party build server. macOS 13 or newer, Apple Silicon, Chrome, and an internet connection for the initial runtime downloads are required.

For local development, an unsigned/ad hoc build may require right-click → Open the first time. To produce a distribution-ready signed and notarized DMG, set `DEVELOPER_ID_APPLICATION` to your Developer ID Application certificate name and `NOTARY_PROFILE` to an Apple notarytool Keychain profile, then run `scripts/package-companion-macos.sh`. Without those values the script still creates a drag-to-Applications DMG, but macOS may show a security warning. Building requires Xcode Command Line Tools; end users do not need them, Homebrew, Node.js, or FFmpeg.
